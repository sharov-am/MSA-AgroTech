Задание 4. Проработка критериев выбора решения

c3_agrotech_mm.puml -- вариант с единым модулем видеоаналитики;
c3_agrotech_ms.puml -- вариант с отдельными модулями для видеоаналитики;

Критерии для сравнения двух решений следующие:
 -- скорость разработки;
 -- отказоустойчивость;
 -- расширяемость;
 -- производительность;
 -- оперативность\скорость реакции;
 -- простота развертывания;

 Скорость разработки.
 
 Варинат с модульным монолитом, кажется, можно будет сделать проще и быстрее. Разработку с нуля, особенно прототипы, лучше начинать с более простых решений.
 Вариант с отдельными модулями видеоаналитики, во-первых, кажется, что дольше будет разрабатываться, плюс, каждый модуль видеоаналитики по сути заточен
 для соотв. объектива  камеры. Например, для модуля пересчета и состояния животных лучше подойдет широкоугольная камера для большего охвата пространства. Данный подход предполагает несколько разных типов объективов камер -- с большим и маленьким фокусным расстоянием. Т.е. под каждый тип объектива свой сервис. Далеко не факт, что это окажется востребованным подходом, хоть камер потребуется и меньше. Вариант с единым сервисом видеоаналитики и унифицированным типом камер может окажется лучше и проще, хотя бы на первое время.

Отказоустойчивость.

С точки зрения отказоустойчивости данные решения эквивалентны. Они оба переиспользует уже работающий подход существующей
цифровой платформы. Проблема может быть в коммуникационном сервисе, который используется для  отправки данных через модем,
на случай сбоя с WIFI (LoRAWAN). Нужно будет иметь, скорее всего, как несколько экземпляров сервиса, так и несколько разных подключенных модемов.
 
Расширяемость.

С точки зрения расширяемости решение с отдельными модулями для видеоаналитики выглядет лучше. Хотя вариант с единым модулем видоеаналитики 
может  оказаться также хорош с тз расширяемости.

Производительность.

По производительности данные решения почти эквивалентны, разве что вариант с единым модулем видеоаналитики будет грузить соотв. edge устройство несколько больше.

Оперативность\скорость реакции

Тут особой разницы между подходами нету, трекинг поведения животных +- одинаков, соотв. скорости уведомления о событиях должны быть одинаковы.

Постота развертывания.

Однозначно подход, где меньше  функциональных модулей (сервисов) 
предпочтительнее. Соотв. вариант с видеоаналитекой в виде модульного монолита более предпочтетелен.

**Резюме** На основе выбранных критериев вариант с модульным монолитом для видеоаналитики  (c3_agrotech_mm.puml) выглядит более предпочтительным -- его относительно быстрее реализовать,
он проще развертывается. Для прототипа это очень хорошо. Минусы с расширяемостью кажется не критичны на данный момент.

Вариант 1. Изоляция на уровне отдельных БД 

Преимущества:

- относительно недорого по стоимост -- несколько серверов, одна лицензия бд;
Недостатки:
- проблема, что при большой нагрузке от одно клиента, пострадают все другие;
- сложно масштабировать;
