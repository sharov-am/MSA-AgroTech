# ADR-3: Проработка критериев выбора решения

**Статус:** ✅ Принято  


---

## 1. Контекст

Среди предложенных вариантов архитектуры (ADR-2) нужно выбрать вариант, который пойдет в разработку.

Task3/c3_agrotech_mm.puml -- вариант с единым модулем видеоаналитики;
Task3/c3_agrotech_ms.puml -- вариант с отдельными модулями для видеоаналитики;
---

## 2. Критерии сравнения 2х решений


| Критерий       | Описание                  | Критичность |
|-----------------|-----------------------------|-------------|
| Скорость разработки | Поскольку речь идет о разработке MVP, то скорость здесь крайне важна.   | Высокая   |
| Отказоустойчивость | Решение должно быть максимально надежным.   | Высокая   |
| Расширяемость | Решение должно быть максимально надежным.   | Низкая   |
| Производительность | Решение должно быть максимально производительным.   | Высокая   |
| Простота развертывания |Сервис должен легко разворачиваться и настраиваться.   | Низкая   |

---

## 3. Решение

### Аргументация

| Критерий         | Обоснование                 |
|------------------|-----------------------------|
|   Скорость разработки               |     Варинат с модульным монолитом, кажется, можно будет сделать проще и быстрее. Разработку с нуля, особенно прототипы, лучше начинать с более простых решений.|

#### Замечание
 Вариант с отдельными модулями видеоаналитики, во-первых, кажется, что дольше будет разрабатываться, плюс, каждый модуль видеоаналитики по сути заточен
 для соотв. объектива  камеры. Например, для модуля пересчета и состояния животных лучше подойдет широкоугольная камера для большего охвата пространства. Данный подход предполагает несколько разных типов объективов камер -- с большим и маленьким фокусным расстоянием. Т.е. под каждый тип объектива свой сервис. Далеко не факт, что это окажется востребованным подходом, хоть камер потребуется и меньше. Вариант с единым сервисом видеоаналитики и унифицированным типом камер может окажется лучше и проще, хотя бы на первое время.      |

 
| Критерий         | Обоснование                 |
|------------------|-----------------------------|
|    Отказоустойчивость              |     С точки зрения отказоустойчивости данные решения эквивалентны. Они оба переиспользует уже работающий подход существующей цифровой платформы. Проблема может быть в коммуникационном сервисе, который используется для  отправки данных через модем, на случай сбоя с WIFI (LoRAWAN). Нужно будет иметь, скорее всего, как несколько экземпляров сервиса, так и несколько разных подключенных модемов.|


| Критерий         | Обоснование                 |
|------------------|-----------------------------|
|    Расширяемость              |  С точки зрения расширяемости решение с отдельными модулями для видеоаналитики выглядет лучше. Хотя вариант с единым модулем видоеаналитики может  оказаться также хорош с тз расширяемости.|

| Критерий         | Обоснование                 |
|------------------|-----------------------------|
|    Производительность              |  По производительности данные решения почти эквивалентны, разве что вариант с единым модулем видеоаналитики будет грузить соотв. edge устройство несколько больше.|

| Критерий         | Обоснование                 |
|------------------|-----------------------------|
|    Постота развертывания              |  Однозначно подход, где меньше  функциональных модулей (сервисов) 
предпочтительнее. Соотв. вариант с видеоаналитекой в виде модульного монолита более предпочтетелен.


**Резюме** На основе выбранных критериев вариант с модульным монолитом для видеоаналитики  (c3_agrotech_mm.puml) выглядит более предпочтительным -- его относительно быстрее реализовать, он проще развертывается. Для прототипа это очень хорошо. Минусы с расширяемостью или возможные проблемы с производительностью кажутся не критичны на данный момент.
