1) Cервис мониторинга поведения.
 В рамках данного сервиса будет осуществляться  мониторинг поведения животынх. Сервис будет
 получить поток видеоданных от одной какой-то камеры и анализировать поведение животных. Отслеживание тревожного поведения  и состояния животных -- драки, задавливание. В общем, любую подозрительную активность или, наоборот, неактивность. В случае, если детектирвано какое-либо тревожное поведение, сервис должен оповещать о них. Для каждого типа определяемого поведения должны задаваться пороги\значения, чтобы уменьшить ложные срабатывания. Сервис должен быть отказоустойчивым(99,95%) и иметь высокую надежность.
 Это наиболее критичный с тз производительности сервис, поскольку на вход будет идти видео поток данных и обрабатываться он будет gpu в около реальном времени (миллисекунды).
 Либо на каждый сервис (инстанс) по gpu, типа jetson nano или что-то вроде, либо 1-2
 мощных gpu на все сервисы.

2) Сервис мониторинга состояния и учета количества.
 Данный сервис предназначен для выяления признаков болезни у животных и учета их количества.
 Сервис может подключаться периодически к какой-либо камеры и анализировать соотв. данные на предмет состояния и количества животных. Например, раз в 1 минуту или раз в 5 минут подключаться ко всем камера по очереди, забирать с них видеопоток и анализировать.
 Либо каждую камеру можно опращивать индивидуально в соответствии с каким-нибудь таймером,
 специально заведенным для этой камеры.

3) Сервис мониторинга и управления  инфраструктурой, обеспечивающей жизнедеятельность животных -- поилки, корм.
 Данный сервис отвечает за управление и контроль за инфраструкторой, необходимой для жизнедеятельности животных. Сервис отвечает за управление, настройку и контроль качества
 поилок и кормушек. В случае достижения каких-то тревожных значений, сервис должен оповещать персонал о соотв. проблеме. 

4) Сервис управления камерами
 Данынй сервис отечает за подключение к систему новых камер, их базовая настройка и т.п. Сервис должен уметь работать с камерами практически любых производителей. 
 Сервис должен предоставлять API для доступа к видеопотоку любой подключенной и работающей камеры.

5) Сервис сбора и хранение видео данных.
 Данный сервис должен собирать видеопоток с камер, нарезать их на видеофрагменты определенной длины и хранить некоторое время. Например, это может быть полезно для какого-нибудь постпроцессинга, который сложно делать на мобильных gpu. Или может быть полезно для сбора "контекстной" информации при наступлении какого-нибудь события. Т.е. если потребуется не только факт наступления какого-нибудь события, но и видеофиксация в окрестности данного события для полноты инфорамции. Видеофайлы с интересующими событиями должны хранится дольше обычных. Сервис
 должен предоставлять соотв. API, как минимум для выгрузки необходимых видеофайлов.

6) Сервис сбора и экспорта метрик.
 Данный сервис должен предоставлять функционал для создания, сбора и экспорта необходимых метрик.

7) Сервис авторизации и аутентификации. 
Данный сервис отвечает за разделение ролей и поддержку современных способов аутентификации и авторизации.

8) Сервис для синхронизации с внешним сервером.
Данный агентский сервис предназначем для отправки событий на какой-то одной конкретной ферме на общий, центральный сервер для всей фермы для учета всех событий.
